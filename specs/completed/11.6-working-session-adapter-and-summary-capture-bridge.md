# Session 11.6 - Working Session Adapter And Summary Capture Bridge

Status: Completed
Owner: Codex
Date: 2026-06-03

## Why This Session Exists

Session 11.5 established HAETSAL's owned working-session boundary:

- transcript entries are volatile and non-canonical
- scratch notes are volatile, bounded, and non-canonical
- context bundles are read-only and non-canonical
- explicit session-close summaries are evidence candidates
- canonical truth remains Postgres/R2 through Hyperdrive

The next narrow step is an internal adapter/capture bridge that can accept
working-session summary evidence emissions and hand their existing
`ExternalClientCaptureInput` shape to a dependency-injected capture sink.

This phase does not wire production agents, tools, routes, bindings, Durable
Objects, or deployment configuration to the new abstraction.

## Goal

Add a production-neutral seam for session-summary capture:

1. define a small working-session adapter interface
2. define a capture sink interface
3. accept `WorkingSessionCanonicalEvidenceEmission[]`
4. send only explicit session-close summary emissions to the sink
5. report captured, skipped, and failed emissions explicitly
6. preserve the HAETSAL write-policy boundary in sink metadata and bridge
   result state

## Boundary

The bridge is an adapter seam, not a runtime integration.

- It imports only local types from the working-session and external-client
  capture contracts.
- It does not import or call live `Env`, MCP context, Durable Objects,
  Cloudflare Sessions, Hindsight, or canonical store implementations.
- It does not import or call `captureExternalClientMemory`.
- It does not change canonical memory behavior.
- It does not register new MCP tools or routes.
- It does not add Cloudflare bindings or Durable Object migrations.
- It does not wire `BaseAgent`, `McpAgentDO`, or production agents to the new
  abstraction.

Only emissions that still prove the explicit summary contract are accepted:

- `kind = "canonical_evidence_emission"`
- `source = "session_close_summary"`
- `summary.kind = "session_close_summary"`
- `summary.canonicalDisposition = "session_summary_evidence_candidate"`
- `summary.requiresHaetsalWritePolicy = true`
- `captureMode = "session_summary"`
- `capture.capture_mode = "session_summary"`
- `writePolicy = "haetsal_write_policy_required"`
- `canonicalTruthBoundary = "postgres_r2_hyperdrive"`

Everything else is skipped before the sink is called.

## Implementation

Added `src/services/working-session-capture-bridge.ts`.

The module defines:

- `WorkingSessionAdapter`
- `WorkingSessionEvidenceCaptureSink`
- `WorkingSessionEvidenceCaptureMetadata`
- `WorkingSessionEvidenceCapturedResult`
- `WorkingSessionEvidenceSkippedResult`
- `WorkingSessionEvidenceFailedResult`
- `WorkingSessionEvidenceCaptureBatchResult`
- `captureWorkingSessionEvidenceEmissions()`
- `captureWorkingSessionAdapterEvidence()`

The sink contract accepts:

- the existing external-client capture input shape
- narrowed to `capture_mode = "session_summary"`
- plus metadata that carries session id, summary id, source, capture mode,
  write-policy boundary, canonical-truth boundary, and
  `requiresHaetsalWritePolicy`

The bridge returns separate `captured`, `skipped`, and `failed` arrays in
addition to the ordered `results` array. Sink failures are reported as failed
results with `acceptedBySink = false`, not promoted to captured results.
