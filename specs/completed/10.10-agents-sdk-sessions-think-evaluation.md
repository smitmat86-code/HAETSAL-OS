Current docs findings:

1. Sessions are still experimental and imported from
   `agents/experimental/memory/session`.
2. Sessions provide persistent conversation history, tree-structured messages,
   context blocks, compaction, full-text search, generated context tools, and
   session management.
3. Default Session storage is Durable Object SQLite, with lazy table creation.
4. Sessions also document custom providers and Postgres providers:
   `PostgresSessionProvider`, `PostgresContextProvider`, and
   `PostgresSearchProvider`.
5. Postgres-backed Sessions require `pg`, a Hyperdrive connection string,
   external table creation, explicit context providers, async method usage, and
   lose SQLite-backed Session broadcaster support.
6. The Memory concept frames Session memory as two kinds of memory:
   conversation history and context memory.
7. Writable short-form context is deliberately model-writable through
   generated `set_context` tools. This is useful for scratchpads but dangerous
   as canonical HAETSAL memory.
8. Think is an opinionated chat agent base class for Workers. It manages chat
   lifecycle, agentic loop, message persistence, streaming, tool execution,
   client tools, stream resumption, extensions, and Session-backed memory.
9. Think docs require installing `@cloudflare/think`, `@cloudflare/ai-chat`,
   `agents`, `ai`, `@cloudflare/shell`, `zod`, and `workers-ai-provider`.
10. Think's documented peers require `agents`, AI SDK v6, Zod v4, and
    `@cloudflare/shell`.
11. Think automatically merges workspace tools, custom tools, Session tools,
    extension tools, MCP tools, and client tools. This needs explicit HAETSAL
    governance before production use.
12. Think supports durable submissions, idempotency keys, chat recovery via
    fibers, sub-agent RPC, programmatic turns, and proactive/scheduled turns.

Current installed package finding:

- `agents@0.7.9` does export `agents/experimental/memory/session`, but its
  installed type surface is much smaller than the current docs. It exports
  `Session` and `AgentSessionProvider` with basic message CRUD and destructive
  micro-compaction. It does not expose the current docs' context blocks,
  SessionManager, generated tools, Postgres providers, or Think integration.

## Brain Laws Check

### Law 1: One Public Face

No public routes, MCP tools, WebSocket paths, or user-facing surfaces are added
or changed.

### Law 2: Zero-Knowledge

No memory content is read from live stores for this spec. No token value,
Postgres URL, transcript, or memory body may be printed into logs, docs, or
commits.

### Law 3: Agent Write Policy

Agent-written memory remains evidence-first through the existing canonical
capture path. Domain agents still cannot write procedural memory directly.

### Law 4: Post-Hindsight Direction

No Hindsight removal or Hindsight runtime change occurs. Hindsight remains a
legacy projection/runtime concern until dedicated removal specs.

### Law 5: Canonical Cloudflare Data Path

Neon/Postgres remains canonical truth through `HYPERDRIVE_CANONICAL` and
HAETSAL's canonical Postgres repository. Sessions, Think, D1, KV, AI Search,
Graphiti, and Hindsight remain non-canonical.

## Decision

Do not adopt current Sessions or Think into production runtime in this spec.

Recommended decision:

1. Defer package/runtime adoption until a scoped dependency migration proves
   Zod 4 and current `agents` are safe.
2. When adopted, use Sessions only for volatile working context, active
   conversation continuity, compaction, and recovery.
3. Wrap Sessions behind HAETSAL-owned agent session/context interfaces.
4. Do not allow Session context blocks or Think model-writable memory to become
   canonical memory.
5. Flow durable session value into canonical Postgres only through the existing
   `capture_memory` / canonical pipeline as evidence, especially
   `capture_mode = "session_summary"`.
6. Defer Think until HAETSAL explicitly wants its opinionated chat lifecycle,
   sub-agent RPC, durable submissions, and tool-merge behavior.

Why:

- Current local `agents@0.7.9` has only an older, reduced Session API. It is not
  the feature set described in current official docs.
- Latest Agents / Think / AI Chat require a Zod 4 migration that is out of
  scope.
- Think's default workspace tools, client tools, Session tools, extension
  tools, and MCP tool merge behavior need explicit policy gates before they can
  safely touch HAETSAL.
- HAETSAL already has a canonical evidence pipeline, retrieval broker, trace
  tooling, and `prepare_context_for_agent`; replacing that with Session memory
  would violate the post-Hindsight plan.
- Sessions are still valuable, but as active working state, not durable truth.

## Dependency Blockers

### Hard Blockers

1. `agents@0.13.3` requires `zod@^4.0.0`; HAETSAL is on `zod@3.25.76`.
2. `@cloudflare/think@0.7.3` requires `agents>=0.12.4 <1.0.0` and `zod@^4.0.0`.
3. `@cloudflare/ai-chat@0.7.2` requires `agents>=0.12.4 <1.0.0` and
   `zod@^4.0.0`.
4. Think also requires `@cloudflare/shell` for workspace filesystem behavior.

### Design Blockers

1. Need a HAETSAL-owned `AgentWorkingSession` abstraction before wiring
   Sessions.
2. Need explicit policy for model-writable context blocks.
3. Need retention and purge rules for raw Session transcript storage.
4. Need tests proving Session summaries enter canonical Postgres as evidence,
   not instruction-grade memory.
5. Need tool allowlists/approval gates before Think workspace, browser,
   extension, client, and MCP tool merging is allowed.
6. Need a decision on SQLite vs Postgres Session providers. SQLite is better
   for active DO-local UX and broadcaster support; Postgres providers are
   useful only if cross-agent session queries or analytics justify storing
   working context in Postgres.

## Phased Modernization Plan

### Phase A - Dependency Readiness, No Behavior Change

- Create a focused Zod 4 and current Agents SDK upgrade spec.
- Upgrade `agents` to current latest only after Zod 4 impact is understood.
- Add `@cloudflare/ai-chat` only if `AIChatAgent` or `useAgentChat` is needed.
- Add `@cloudflare/think` only in a later Think-specific spec.
- Run MCP route, DO identity, generated type, full test, and postflight checks.
- Do not adopt Sessions or Think behavior in this phase.

### Phase B - HAETSAL Session Abstraction

- Define HAETSAL-owned interfaces for:
  - active conversation history
  - writable scratch context
  - read-only context blocks
  - session close summaries
  - canonical evidence emission
- Keep the implementation behind an adapter so HAETSAL can choose DO SQLite,
  Postgres providers, or a test store without leaking Cloudflare API shapes
  into product memory semantics.
- Add a policy distinction between:
  - working notes
  - evidence summaries
  - canonical captures
  - instruction-grade memory

### Phase C - Sessions Pilot, SQLite First

- Pilot Sessions in one non-public or first-party agent path.
- Use Durable Object SQLite by default for active working context and UX
  continuity.
- Use bounded retention and explicit cleanup.
- Treat generated `set_context` writes as scratchpad updates only.
- On session close, emit a summary through `capture_memory` with
  `capture_mode = "session_summary"`.
- Add tests proving full transcripts are not promoted to canonical truth by
  default.

### Phase D - Context Provider Wrapping

- Wrap read-only context providers around `prepare_context_for_agent`.
- Wrap search providers around HAETSAL's retrieval broker only if the provider
  returns cited, scoped, provenance-carrying results.
- Keep canonical retrieval policy in HAETSAL code, not in Cloudflare Session
  provider defaults.
- For writable context, allow only bounded working state and explicit summary
  capture.

### Phase E - Postgres Session Provider Decision

- Use Postgres providers only if HAETSAL needs cross-Durable Object session
  search, analytics, shared working context, or centralized retention.
- If adopted, keep Session tables separate from canonical truth, preferably in
  a clearly named non-canonical schema.
- Do not store canonical facts, claims, procedures, or promoted memory in
  `assistant_messages` or `cf_agents_context_blocks`.
- Record retention/purge and DLP rules before storing raw session text outside
  the Agent DO.

### Phase F - Think Pilot Behind Policy Gates

- Pilot Think only after current Agents and AI Chat dependencies are stable.
- Disable or tightly allowlist workspace, browser, extension, execute, client,
  and MCP tool surfaces.
- Use Think's durable submissions and chat recovery only for agent-turn
  lifecycle, not memory truth.
- Require all durable memory writes to pass through HAETSAL's canonical
  capture/write-policy interfaces.
- Add tests for tool merge order, approval gating, context summary emission,
  and no direct canonical-memory bypass.

### Phase G - Production Adoption

- Adopt Sessions/Think only after the pilot proves:
  - no Hindsight dependency is deepened
  - MCP behavior remains stable
  - canonical memory remains Postgres/R2 truth
  - session summaries are captured as evidence
  - agent context bundles are sourced through HAETSAL retrieval interfaces
  - working context retention is bounded
  - tests cover transcript retention, compaction, summary capture, and
    canonical write boundaries
