# Session 11.5 - Working Session Abstraction And Summary Boundary

Status: Completed
Owner: Codex
Date: 2026-06-03

## Why This Session Exists

Sessions 11.0 through 11.4 moved HAETSAL back toward its own post-Hindsight
memory architecture:

- canonical truth in Postgres/R2 through Hyperdrive
- compiled synthesis as HAETSAL-owned read models
- Chief-of-Staff context preferring compiled assets
- connector-triggered compilation refreshes from canonical writes

The remaining architecture gap before any future session-provider adoption is a
HAETSAL-owned working-session contract. The contract must make active
conversation state useful without letting volatile session material become
canonical memory by accident.

## Goal

Define the narrow internal boundary for working sessions:

1. active conversation history
2. bounded scratch context
3. read-only context bundles
4. session-close summaries
5. canonical evidence emission from explicit summaries only

No production agent, MCP tool, route, binding, Durable Object migration,
deployment config, or canonical memory behavior changes in this phase.

## Boundary

Working-session state is not canonical truth.

- Active conversation history is volatile and non-canonical.
- Scratch context is volatile, bounded, and non-canonical.
- Context bundles are read-only inputs sourced from existing context/read paths.
- Session-close summaries are evidence candidates.
- Canonical truth remains Postgres/R2 through Hyperdrive.
- Instruction-grade memory must still pass HAETSAL write policy through the
  existing canonical capture path.

Durable value from a working session may enter the brain only as an explicit
session-close summary, represented as `capture_mode = "session_summary"` for
the existing `capture_memory` contract.

## Implementation

Added `src/services/working-session.ts` as a small internal abstraction module.

The module defines:

- `WorkingSessionTranscriptEntry`
- `WorkingSessionScratchNote`
- `BoundedWorkingScratchContext`
- `WorkingSessionContextBundleRef`
- `WorkingSessionCloseSummary`
- `WorkingSessionCanonicalEvidenceEmission`
- `WORKING_SESSION_BOUNDARY`

The only canonical bridge is:

- `buildSessionSummaryEvidenceEmission(summary)`
- `collectCanonicalEvidenceEmissions(artifacts)`

Those helpers filter for `session_close_summary` artifacts and produce the
existing external-client capture input shape with:

- `capture_mode = "session_summary"`
- `memory_type = "episodic"`
- `provenance = "agent_authored"`
- session id, title, client name, scope, and content from the explicit summary
