which tree is the implementation baseline.

branch.

## Implementation Steps

### 1. Choose the Implementation Baseline

Default decision:

- use `C:\Users\matth\Documents\HAETSAL OS 11.4 deploy`
- branch from `codex/11-4-deploy-candidate`

Only reject this default if inspection shows the 11.4 tree is missing the
canonical Postgres or compiled-synthesis work named in the 10.0 report.

### 2. Create the Reconciliation Branch

In the 11.4 tree:

```powershell
git switch -c codex/post-hindsight-cloudflare-reconciliation
```

If the branch already exists:

```powershell
git switch codex/post-hindsight-cloudflare-reconciliation
```

If dirty files prevent switching, stop and report. Do not stash or reset without
explicit user approval.

### 3. Bring in Planning Docs

Cherry-pick the committed planning output onto the reconciliation branch:

```powershell
git cherry-pick 64eb362
git cherry-pick 34734b5
git cherry-pick f27d057
```

If this 10.1 spec has a committed hash available in the source planning tree,
also cherry-pick it.

If a cherry-pick conflicts only in docs/spec files, resolve conservatively and
continue. If it conflicts in runtime code, stop and report.

### 4. Clean the Active Spec Queue

If the 11.4 tree still has completed work under `specs/active/`, move completed
As-Built specs to `specs/completed/`.

Do not invent an As-Built for an active spec that is not already complete.

### 5. Fix Test Discovery

Adjust Vitest configuration so default test discovery is scoped to HAETSAL's own
tests.

Preferred shape:

```ts
test: {
  include: ['tests/**/*.test.ts'],
  exclude: [
    '**/node_modules/**',
    '**/.git/**',
    '**/.codegraph/**',
    'gbrain/**',
    'OB1/**',
    'Second-Brain/**',
  ],
  setupFiles: ['./tests/apply-migrations.ts'],
  fileParallelism: false,
  maxWorkers: 1,
  minWorkers: 1,
  onConsoleLog(log) {
    return !QUIET_TEST_LOG_PREFIXES.some(prefix => log.startsWith(prefix))
  },
}
```

Follow the local file's formatting and keep the edit minimal.

### 6. Verify Package Manifest Consistency

Do not upgrade packages.

Check whether direct dependencies in `package.json` and the root
`package-lock.json` package entry agree for important Cloudflare/Neon packages:

- `@cloudflare/containers`
- `@cloudflare/workers-types`
- `@neondatabase/serverless`
- `agents`
- `wrangler`

If there is only lockfile resolution drift within package ranges, record it.
If `package-lock.json` contains a root dependency that is absent from
`package.json`, fix the manifest/lock mismatch only if the correct dependency is
obvious from the 11.4 runtime code.

Do not run dependency update commands that change package versions as part of
this session.
