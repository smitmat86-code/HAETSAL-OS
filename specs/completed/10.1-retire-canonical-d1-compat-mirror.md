## What We're Building

Remove the temporary **canonical D1 metadata compatibility mirror** introduced
in Session 10.0.

After 10.0, Postgres is authoritative on paper and in most of the runtime, but
the system still mirrors canonical metadata rows into D1 for compatibility.

Session 10.1 makes the cutover real everywhere it matters:

- canonical memory families stay only in Postgres + R2
- D1 no longer stores mirrored canonical metadata for those families
- D1 remains only for the roles we deliberately still want there

This is the cleanup step that turns `10.0` from “authoritative with compatibility
shadow” into “authoritative in practice.”

---

## Why This Session Exists

Session 10.0 explicitly left one piece of debt:

- `src/services/canonical-d1-compat.ts`
- a narrow temporary D1 mirror of canonical metadata

That was the right migration step to keep the system stable during cutover.

But it is still architectural drift from the target:

- canonical truth should not be duplicated into D1 once the cutover is proven

Now that:

- Hindsight is green
- Graphiti is green
- broker is green
- tenant trace is green
- Postgres canonical truth is landed

we should remove the compatibility mirror.

---

## Strategic Scope

### In Scope

- remove the temporary D1 canonical metadata mirror
- remove runtime reads/writes that still depend on that mirror
- keep Postgres as the only authoritative store for canonical memory families
- keep D1 for broker traces and control-plane state only
- keep public tool contracts stable
- rerun full live acceptance to confirm Hindsight/Graphiti stay green

### Explicitly Out of Scope

- broker redesign
- tenant trace redesign
- platform analytics
- Hindsight or Graphiti replacement
- Graphiti durability redesign
- full D1 elimination

---

## Canonical Storage Boundary After 10.1

### Postgres + R2

Authoritative for:

- `canonical_captures`
- `canonical_artifacts`
- `canonical_documents`
- `canonical_chunks`
- `canonical_memory_operations`
- `canonical_projection_jobs`
- `canonical_projection_results`

### D1

Still allowed for:

- `canonical_broker_traces`
- `memory_audit`
- `hindsight_operations`
- tenant/control-plane/runtime-local state

Not allowed after 10.1:

- mirrored canonical metadata rows for the canonical memory families above
