# Session 11.3 - Chief Of Staff Compiled Read Path

Status: Active
Owner: Codex
Date: 2026-04-22

## Why This Session Exists

Session 11.0 established the compiled-synthesis foundation.

Session 11.1 refined the compiled output model.

Session 11.2 built the first real compiler and began materializing dossiers,
context packs, and change-oriented compiled outputs.

What is still missing is the first meaningful product-facing read-path shift:

- the Chief of Staff should start reading the compiled layer first

This session is where the re-aligned architecture begins to affect real HAETSAL
behavior.

## Goal

Introduce a compiled-first read path for the Chief of Staff that:

1. prefers compiled context assets over ad hoc runtime composition
2. uses dossiers/context packs/change views as the primary high-value inputs
3. stays additive without breaking the current production memory path
4. preserves room for direct sessions and specialist agents to continue using
   the brain independently

This is not a full product cutover. It is the first real read-path adoption of
the compiled layer.

## Non-Goals

- Do not redesign the entire MCP surface.
- Do not remove the current production memory path.
- Do not remove existing memory tools.
- Do not reintroduce Hindsight or Graphiti as foundational dependencies.
- Do not make the Chief of Staff the sole reader/writer of the brain.
- Do not turn this session into a general UI/browser layer.

## Strategic Intention

The point of re-aligned HAETSAL is not just to store compiled outputs.

It is to make them the primary source of understanding for the system's main
operator.

This session should make the Chief of Staff:

- feel more coherent
- rely less on runtime reconstruction
- rely more on durable compiled understanding

while still allowing:

- direct working sessions
- specialist agents
- future project integrations

to use the same brain through their own paths.

## Scope

This session should shift the Chief-of-Staff-oriented read path to prefer
compiled outputs.

### Required read families

At minimum, use compiled artifacts for:

1. context packs
2. dossiers
3. recent-change summaries

The exact internal route may vary, but the read path should be explicitly
compiled-first.

### Recommended first target

The best first target is the existing context-building path, likely centered on:

- `prepare_context_for_agent`
- Chief-of-Staff-oriented internal context assembly services

This session should adapt that path to prefer:

- compiled context packs
- compiled dossiers
- compiled change views

before falling back to older runtime composition paths if necessary.

## Read-Path Rules

### Rule 1 - Compiled first

For Chief-of-Staff-oriented context:

- prefer the latest compiled context pack when available
- augment from compiled dossiers where relevant
- augment from recent-change/decision views where relevant

### Rule 2 - Fallback, not breakage

If compiled outputs are missing, stale, or incomplete:

- fall back truthfully to the older path
- do not fail the request unnecessarily
- surface enough metadata to make it debuggable

### Rule 3 - Preserve other readers/writers

This session should not force all other agents or direct sessions through the
Chief of Staff read path.

The goal is:

- compiled-first for the primary operator
- not monopoly control by that operator

## What Should Change

### Context assembly

Introduce or update a context assembly service that:

- loads compiled context packs first
- hydrates dossier support where useful
- adds recent-change/decision support
- emits a coherent agent-ready context object

### Provenance

The Chief of Staff should still be able to understand:

- what compiled artifacts were used
- when they were compiled
- what fallback was used if compiled assets were missing

### Freshness

Define a minimal freshness policy for compiled outputs used by the Chief of
Staff.

For example:

- prefer latest successful compiled version
- allow stale-but-usable with explicit metadata
- only fall back if no acceptable compiled asset exists

The exact thresholds can remain modest in this session, but the policy should be
explicit.

## Product-Surface Expectations

This session may update:

- `prepare_context_for_agent`
- related internal context assembly/read services

It should avoid:

- broad MCP redesign
- broad new browsing features
- large new public tool families

Keep the product-facing change focused: the Chief of Staff starts preferring the
compiled brain.

## Verification

Add or tighten tests for:

- Chief-of-Staff-oriented context prefers compiled context packs
- dossier augmentation is used when available
- recent-change/decision compiled views are incorporated
- fallback to older runtime path works when compiled outputs are missing
- provenance/freshness metadata is preserved
- direct existing production memory path is not broken

Run at minimum:

- dedicated `11.3` test file(s)
- relevant 11.0 / 11.1 / 11.2 compiled-synthesis tests
- relevant context-builder tests
- `npm test`
- `npm run postflight`
- `npm run manifest`

## Local Proof

Before finishing:

- verify Chief-of-Staff-oriented context can be assembled from compiled outputs
- verify fallback still works when compiled outputs are absent
- verify existing production memory flows are still functional
- explicitly state whether any compatibility shim was required

## Deliverable

At the end of this session, HAETSAL should have:

1. a compiled-first read path for the Chief of Staff
2. dossiers/context packs/change views actually affecting real context assembly
3. truthful fallback behavior
4. preserved compatibility with the existing production memory path
5. a clean base for the next phase of connector growth and broader compiled read
   adoption

- **Compiled-First Chief-of-Staff Read Path**
  - `prepareContextForAgent` now tries a Chief-of-Staff-only compiled read path before the older runtime brokered search path.
  - The compiled lookup is stable-key based and currently targets the existing 11.1 / 11.2 families already on disk:
    - context packs:
      - `context-pack:chief-of-staff:{slug}`
      - `context-pack:project:{slug}`
      - `context-pack:person:{slug}` when intent is `person`
    - dossiers:
      - `dossier:project:{slug}`
      - `dossier:person:{slug}` when intent is `person`
    - change / decision views:
      - `what-changed:{kind}:{slug}`
      - `what-changed:{slug}`
      - `decision-log:{kind}:{slug}`
      - `decision-log:{slug}`
  - A fresh, source-linked, agent-usable compiled context pack is now the gate for compiled-first assembly.
  - When that gate passes, the returned bundle is assembled primarily from:
    - compiled context pack situation / critical facts / recent changes / decisions / contradictions / recommended actions
    - compiled dossier why-it-matters / current state / relationships / open questions when a fresh dossier is available
    - compiled `what_changed` and `decision_log` views when fresh and complete

- **Freshness / Fallback Policy**
  - Added explicit compiled metadata to the returned context bundle via `compiled`.
  - `compiled` now records:
    - whether the bundle was `compiled_first` or `runtime_fallback`
    - whether fallback was used
    - why fallback happened
    - the freshness policy string
    - per-asset usage metadata:
      - availability
      - whether the asset was actually used
      - stable key
      - compiled timestamp
      - freshness classification
      - completeness classification
      - source count
  - 11.3 freshness threshold is now explicit:
    - compiled context packs older than 7 days are treated as stale
    - stale or incomplete primary compiled context packs fall back to the prior runtime composition path
    - stale or incomplete dossier / change / decision augments are skipped with preserved gap metadata rather than failing the request

- **Existing Production Path Preserved**
  - The older runtime composition path was extracted intact into `chief-of-staff-context-runtime.ts`.
  - When compiled outputs are missing, stale, incomplete, or the compiled store is unavailable, `prepareContextForAgent` truthfully falls back to the existing canonical runtime read path.
  - The canonical memory MCP tool surface was preserved; `prepare_context_for_agent` still calls the same service and no existing memory tools were removed.
