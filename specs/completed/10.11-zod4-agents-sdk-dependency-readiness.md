## Official Docs Checked

Checked on 2026-06-02:

- Cloudflare Agents Sessions:
  `https://developers.cloudflare.com/agents/api-reference/sessions/`
- Cloudflare Agents Think:
  `https://developers.cloudflare.com/agents/api-reference/think/`
- Cloudflare Chat agents:
  `https://developers.cloudflare.com/agents/api-reference/chat-agents/`
- Cloudflare AI SDK v6 migration:
  `https://developers.cloudflare.com/agents/guides/migration-to-ai-sdk-v6/`
- Zod 4 migration guide:
  `https://zod.dev/v4/changelog`

Docs findings:

1. Current public Sessions docs describe the Session API as experimental under
   `agents/experimental/memory/session`.
2. Public Sessions docs describe persistent conversation storage,
   tree-structured messages, context blocks, compaction, full-text search, and
   AI-controllable tools.
3. Public Sessions docs currently emphasize Durable Object SQLite and say no
   external database is needed.
4. The Agents SDK docs index/search still surfaces broader Session provider
   material, including custom providers and Postgres provider examples. Treat
   that as upstream capability evidence, not a reason to adopt Sessions here.
5. Think docs describe `@cloudflare/think` as an opinionated chat agent base
   class that owns chat lifecycle, message persistence, streaming, tool
   execution, client tools, stream resumption, extensions, and DO SQLite-backed
   state.
6. Think docs install `@cloudflare/think`, `@cloudflare/ai-chat`, `agents`,
   `ai`, `@cloudflare/shell`, `zod`, and `workers-ai-provider`.
7. Chat agent docs describe `@cloudflare/ai-chat` as providing `AIChatAgent`
   and `useAgentChat`, with automatic SQLite message persistence, resumable
   streaming, WebSocket sync, and tool support.
8. Zod 4 docs confirm that `ZodInvalidEnumValueIssue` was merged into
   `$ZodIssueInvalidValue`, which changes the issue code observed by tests.
9. Zod 4 docs confirm that single-argument `z.record(valueSchema)` usage is no
   longer supported; the Zod 4 form is `z.record(keySchema, valueSchema)`.

Policy conclusion:

- Do not adopt Sessions, Think, AI Chat, or new memory/session behavior in this
  dependency migration.
- If Sessions are ever adopted later, they remain non-canonical working context
  only.

```powershell
npm install zod@latest --ignore-scripts
npx tsc --noEmit --pretty false src\tools\act\run-playbook.ts tests\3.2-memory-interface.test.ts

```

Results:

  `src/tools/act/run-playbook.ts`: `z.record(z.string())` now expects 2-3
  arguments.
- Focused Vitest failed one assertion:
  expected `invalid_enum_value`, received `invalid_value`.
- The remaining 8 tests in `tests/3.2-memory-interface.test.ts` passed.

Zod-only conclusion:

- Zod 4 migration is low-code, not no-code.
- Required behavior-neutral edits are limited to `runPlaybookSchema.parameters`
  and the enum-error-code test expectation.

### Zod 4 + Current Agents Trial

Command shape:

```powershell
npm install zod@latest agents@latest --ignore-scripts
npx tsc --noEmit
npx vitest run tests/3.2-memory-interface.test.ts
```

Results:

- Install succeeded with current `zod` and `agents`.
- The targeted Zod-memory test failed for the same enum issue-code change.
- The TypeScript probe produced many baseline/plain-`tsc` errors, plus these
  readiness signals relevant to the Agents/Zod upgrade:
  - `src/tools/act/run-playbook.ts`: `z.record(z.string())` must be rewritten.
  - `src/workers/mcpagent/do/McpAgent.ts`: latest `McpAgent` types constrain
    `Env` against `Cloudflare.Env`; the manual `src/types/env.ts` is behind the
    generated `src/types/cloudflare-env.generated.d.ts` shape.
  - `src/workers/mcpagent/do/McpAgent.ts`: latest `this.sql` typing accepts
    SQL values as `string | number | boolean | null`; `SessionSql` should be
    tightened from `unknown[]` to that value union or wrapped with a typed
    adapter.
  - `src/workers/mcpagent/index.ts`: namespace typing for `McpAgentDO` is tied
    to the same `Env` alignment issue.

Agents conclusion:

- Current `agents` can be upgraded after Zod 4 without adopting Sessions,
  Think, or AI Chat.
- The package upgrade is not purely manifest-only. It needs small type-readiness
  edits around manual Env alignment and `SessionSql`, plus the Zod edits above.
- No trial result required a runtime behavior change, new binding, new DO
  migration, Sessions import, Think import, AI Chat import, or Hindsight
  removal.

canonical memory only through the existing evidence capture path, such as
