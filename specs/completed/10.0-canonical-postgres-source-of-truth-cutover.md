## What We're Building

Move the **canonical open-brain source of truth** from the current D1 bridge to
the long-term target defined in the architecture:

- **Postgres + R2** for canonical memory truth
- **Hindsight** as semantic projection
- **Graphiti** as graph/temporal projection
- **Cloudflare** as orchestration shell

This session is the first real storage cutover. It does **not** redesign the
broker, tenant trace product, or engine behavior. It changes where canonical
memory truth lives.

When complete:

- canonical capture/document/chunk/operation/projection truth lives in Postgres
- D1 stops being the canonical substrate for those memory families
- D1 remains for Cloudflare-local control-plane state where it still makes sense
- public tool contracts stay stable

---

## Why This Session Exists

The repo already proved the broker and tenant trace layers:

- `9.8` shipped primary + shadow broker behavior
- `9.9` shipped tenant-visible trace readback

The biggest remaining drift from the architecture target is structural:

- canonical memory truth is still mostly **D1 + encrypted R2**
- the architecture target says it should become **Postgres + R2**

This session closes that gap.

---

## Decisions Already Locked

These are **not** open questions anymore for this session:

- Hindsight stays
- Graphiti stays
- broker remains the default read layer
- broker shadow behavior stays
- tenant trace remains tenant-first
- platform-owner observability remains out of scope for now

This session is about **canonical storage**, not product-surface philosophy.

## Strategic Scope

### In Scope

- canonical Postgres schema for canonical memory families
- Worker-side Postgres repository/service layer
- cutover of canonical writes from D1-first to Postgres-first
- compatibility mirror only where current runtime still depends on D1 rows
- canonical read/status/query services updated to use Postgres truth
- Hindsight and Graphiti reconciliation reading canonical identity from Postgres
- live regression proof that Hindsight and Graphiti remain green

### Explicitly Out of Scope

- broker redesign
- platform analytics
- trace-product redesign
- replacing Hindsight or Graphiti
- Graphiti durability redesign
- full D1 elimination
- session/working-memory changes

## Target State For This Session

### Canonical truth moves to Postgres

Postgres becomes authoritative for:

- `canonical_captures`
- `canonical_artifacts`
- `canonical_documents`
- `canonical_chunks`
- `canonical_memory_operations`
- `canonical_projection_jobs`
- `canonical_projection_results`

### R2 remains canonical for raw encrypted artifacts

R2 continues to store:

- encrypted raw bodies
- file artifacts
- large archives

### D1 remains only for Cloudflare-local support roles

Allowed D1 roles after this session:

- broker traces
- local operational metadata that is genuinely Cloudflare-native
- legacy compatibility rows only if still required during cutover

Not allowed after this session:

- D1 as the primary truth store for canonical memory families above

---

## Storage Decision

Use the **existing Neon/Postgres environment** as the first canonical Postgres
landing zone.

Recommended posture:

- one Neon cluster
- separate canonical schema ownership from Hindsight-owned schema/tables
- Worker-side access through a real Postgres client suitable for Workers
- no “route canonical writes through the Hindsight container” shortcut

This session should choose the smallest real Worker->Postgres path that keeps
the architecture honest.

Recommended implementation default:

- add a Worker-safe Postgres client library
- use `NEON_CONNECTION_STRING` initially unless a distinct canonical secret is
  required by the runtime
- if a distinct canonical connection secret becomes necessary, document it
  explicitly in As-Built

---

## THE Brain Laws Check

### Law 1: One Public Face

No new public API bypasses the Worker/McpAgent surface.

### Law 2: Zero-Knowledge

Raw memory content must still not land in D1, KV, or Analytics Engine. Postgres
canonical rows must follow the same encrypted/raw-pointer split already used by
the bridge design.

### Law 3: Agent Write Policy

This is a storage cutover only. No widening of write authority.

## Behavioral Wiring

### Authorization

| Route / Entry Point | Auth Level | Tenant ID Source | When Checked |
|---------------------|-----------|-----------------|-------------|
| existing canonical memory tools | existing auth/session path | existing tenant context | existing auth middleware + DO bootstrap |
| internal canonical Postgres repository | trusted internal caller | service arg / tenant context | at service boundary |

No new public route is added.

### Audit

Audit semantics must stay truthful through the cutover:

- capture accepted
- projection queued
- projection reconciled
- capture failed

No regression in audit truth is allowed.

### Compute Routing

| Operation | Tier | Rationale |
|-----------|------|-----------|
| canonical write to Postgres | sync Worker/service | source-of-truth write |
| encrypted artifact write to R2 | sync Worker/service | part of canonical acceptance |
| optional D1 compatibility mirror | sync Worker/service | temporary migration bridge |
| projection fan-out | existing async lanes | unchanged behavior |

## Part 2: Schema

Create a real Postgres schema for the canonical memory families.

Required tables:

- `canonical_captures`
- `canonical_artifacts`
- `canonical_documents`
- `canonical_chunks`
- `canonical_memory_operations`
- `canonical_projection_jobs`
- `canonical_projection_results`

Required properties:

- `tenant_id` on all tenant-scoped tables
- indexes for tenant/time/status lookup
- parity with the D1 bridge shape where possible
- no raw plaintext memory bodies in relational rows when the canonical design
  says the backing content should live encrypted in R2

The schema file should be **Postgres-specific**, not another D1 migration.

---

## Part 3: Repository / Service Contract

Introduce a canonical repository abstraction so the rest of the code stops
talking directly to D1 for canonical truth.

Expected shape:

```typescript
export interface CanonicalMemoryStore {
  captureWrite(...)
  getCapture(...)
  getDocument(...)
  getOperation(...)
  listProjectionJobs(...)
  updateProjectionResult(...)
}
```

This session should not leave canonical truth split across ad hoc D1 and
Postgres calls.

---

## Part 4: Cutover Strategy

Recommended cutover:

### Step A

Land Postgres schema and repository.

### Step B

Change canonical writes to:

1. write Postgres canonical truth
2. write encrypted R2 artifact/document payloads
3. write optional D1 compatibility rows only where still needed

### Step C

Change canonical read/status/reconciliation paths to read from Postgres truth.

### Step D

Leave broker traces in D1 for now.

This is important. Broker traces are **not** the primary cutover target.

---

## Part 5: D1 Compatibility Bridge

The goal is **not** “delete D1 immediately.”

The goal is:

- remove D1 as the primary store for canonical memory families
- keep narrow D1 compatibility only where current runtime still depends on it

Any remaining D1 dependency after this session must be explicitly listed in
As-Built:

- what still uses D1
- why it still uses D1
- what later session removes it
